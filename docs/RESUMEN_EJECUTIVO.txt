PREGUNTA
--------
¿Es viable hacer directamente desde n8n para escribir en BD?
¿Cómo conectar la BD al dashboard?

RESPUESTA: ✅ SÍ, ES 100% VIABLE
================================================================================

QUÉ NECESITAS
=============

1. PostgreSQL 16 (container)
   - 5 tablas: carga, proyecto, revenue_mes, revenue_anual, movimiento
   - 3 vistas: v_carga_actual, v_proyecto_actual, v_revenue_quarter
   - ~1.5 MB por carga (349 proyectos × 12 meses)

2. API Node.js (container)
   - 3 endpoints: GET /api/proyectos, /backlog, /historia
   - Lee de PostgreSQL, devuelve JSON (estructura igual a la actual)
   - 100 líneas de código

3. n8n (container)
   - Orquesta: Drive trigger → descarga Excel → ejecuta etl.py → recarga API
   - Sin cambios, solo agregar variables de conexión a Postgres

4. Cambios en código existente:
   - etl.py: agregar función write_to_postgres() (~50 líneas)
   - index.html: cambiar 3 fetch URLs (de data/*.json a http://api:3000/api/*)
   - app.js: SIN CAMBIOS
   - dashboard: SIN CAMBIOS

STACK TECNOLÓGICO
=================

┌─────────────┐
│   Docker    │  docker-compose.yml (3 servicios)
├─────────────┤
│ PostgreSQL  │  Schema: 5 tablas + 3 vistas + índices
│ 16          │  Transacciones ACID, deduplicación por hash
├─────────────┤
│ Node.js 20  │  Express REST API
│ + Express   │  Pool de conexiones a BD
│ + pg        │  3 endpoints (proyectos, backlog, historia)
├─────────────┤
│ n8n         │  Trigger + Download + Execute Command (etl.py)
│ (local)     │  Env vars: POSTGRES_HOST, POSTGRES_PORT, etc.
├─────────────┤
│ Python 3    │  etl.py modificado: --destino=postgres
│ + openpyxl  │  Lee Excel, escribe en Postgres (en transacción)
│ + psycopg3  │
└─────────────┘

VENTAJAS
========

1. ✅ Histórico REAL (no simulado)
   - Cada carga es un snapshot verdadero
   - 32 cargas hoy → 365 en un año

2. ✅ Deduplicación automática
   - Hash SHA256 evita escribir si no cambió
   - Excel se refresha cada 4 horas

3. ✅ Transacciones (todo o nada)
   - Si falla en el medio, rollback automático
   - No quedan cargas a medias

4. ✅ Trazabilidad precisa
   - Tabla movimiento registra EXACTAMENTE qué cambió
   - Por proyecto × mes × carga

5. ✅ Dashboard sin reescribir
   - Misma estructura de JSON
   - Solo 3 líneas de fetch nuevas

6. ✅ Escalable
   - Postgres maneja fácil 1000+ cargas
   - Vistas para cálculos complejos
